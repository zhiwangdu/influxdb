# 04. 质量门禁与场景化 Playbooks

## 1. 通用质量门禁（建议）

### 1.1 静态与单元层

- `go test ./...`（至少覆盖受影响包）
- `go test -race`（并发敏感模块优先：`coordinator` / `tsdb` / `services`）
- 格式化与 vet 检查

### 1.2 集成层

- HTTP 写入/查询端到端验证
- Meta 与 shard 相关行为验证
- 配置热加载（若涉及）验证

### 1.3 性能层

- 写入吞吐（points/s）
- 查询延迟（P50/P95）
- 启动时长、内存峰值、WAL/TSM 读写放大

### 1.4 兼容性层

- API 参数兼容
- 配置默认值兼容
- 旧数据文件/索引可读性兼容

## 2. Playbook A：写入链路改动（services → coordinator → tsdb）

**适用**：line protocol 解析、写入限流、批量写优化、WAL 行为调整。

**规格重点**：

- 写入成功/失败语义（状态码、错误消息）
- 幂等性和部分失败策略
- 写入性能预算（吞吐、延迟、资源）
- 回滚开关（feature flag）

**最小测试集**：

1. 正常写入 + 查询可见性。
2. 非法输入错误码稳定性。
3. 并发写入下的数据一致性。
4. 性能对比（基线 vs 新实现）。

## 3. Playbook B：查询执行改动（query/coordinator/tsdb cursor）

**适用**：执行计划、语义修复、聚合性能优化。

**规格重点**：

- SQL 语义保持（含边界条件）
- 结果集顺序/精度/空值处理
- 超时与并发上限策略

**最小测试集**：

1. 历史 bug 回归查询。
2. 多 RP / 多 shard 结果一致性。
3. 慢查询日志与超时行为验证。
4. Benchmark（常见聚合与过滤组合）。

## 4. Playbook C：配置与服务接入改动（services/*）

**适用**：HTTPD、Graphite、Collectd、OpenTSDB、UDP 等服务配置扩展。

**规格重点**：

- 配置键默认值、动态重载能力、向后兼容。
- 对认证授权与 TLS 的影响。
- 失败时降级策略（禁用子服务、不影响主流程）。

**最小测试集**：

1. 默认配置启动可用。
2. 新配置启用后行为符合预期。
3. 非法配置错误提示清晰。
4. reload 后配置生效验证（若支持）。

## 5. Playbook D：存储格式/索引演进（高风险）

**适用**：TSM/WAL/TSI 读写行为、索引构建逻辑、压缩策略。

**规格重点**：

- 文件格式兼容矩阵（老写新读/新写老读）
- 升级与回滚路径
- 数据恢复与修复工具适配（`influx_inspect`）

**最小测试集**：

1. 旧数据集回放可读。
2. 宕机恢复完整性验证。
3. 压缩/重建后查询结果一致。
4. 修复工具输出契约验证。

## 6. PR 模板增强建议（配合 SDD）

在 PR 描述中增加：

- Spec ID
- 受影响模块
- 契约变化摘要（API/配置/数据）
- 测试证据
- 回滚方案

这样可以让评审更快判断“实现是否真正满足规格”。
