# 04. 质量门禁与场景化 Playbooks

## 1. 统一质量门禁

### 1.1 静态与单测

- 受影响包 `go test`
- 并发敏感模块 `go test -race`
- 格式化 + vet（与仓库规范一致）

### 1.2 集成验证

- 写入/查询端到端
- 配置生效（含 reload 场景如适用）
- Meta/shard 相关行为一致性

### 1.3 性能预算

- 写入吞吐（points/s）
- 查询延迟（P50/P95/P99）
- 内存峰值与启动耗时

### 1.4 兼容性

- API 参数与错误语义兼容
- 配置默认值兼容
- 数据文件/索引可读性兼容

---

## 2. Playbook A：写入链路（services → coordinator → tsdb）

**重点**：状态码语义、部分失败策略、写入预算、可回滚。

**最小测试集**：

1. 正常写入后可查询。
2. 非法输入错误码稳定。
3. 并发写入一致性。
4. 开关前后性能对比。

## 3. Playbook B：查询链路（query/coordinator/tsdb cursor）

**重点**：语义一致性、排序/精度/空值、超时与并发策略。

**最小测试集**：

1. 历史问题回归查询。
2. 多 RP / 多 shard 一致性。
3. 慢查询日志与 timeout 行为。
4. 聚合+过滤 benchmark。

## 4. Playbook C：服务配置扩展（services/*）

**重点**：默认值、动态重载、认证与 TLS 影响、失败降级。

**最小测试集**：

1. 默认配置可启动。
2. 新配置启用行为正确。
3. 非法配置报错可读。
4. reload 生效验证（若支持）。

## 5. Playbook D：存储/索引演进（高风险）

**重点**：格式兼容矩阵、升级回滚路径、修复工具配套。

**最小测试集**：

1. 旧数据可读回放。
2. 异常重启恢复完整性。
3. 重建/压缩前后查询一致性。
4. `influx_inspect` 输出契约校验。

## 6. PR 证据模板（建议）

- Spec ID：`SPEC-YYYY-NNN`
- Contract Delta：API / Config / Data
- Test Evidence：命令 + 结果
- Rollout：灰度策略
- Rollback：执行步骤
